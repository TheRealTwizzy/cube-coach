# Cube Coach: Patterns mode

## Context
User wants to be able to make "all the 3x3x3 cube patterns" (checkerboard, superflip, cube-in-cube, …) with the same animated, turn-by-turn guidance the solver has. Decisions agreed in chat:
- Library of ~110 named patterns (ruwix.com gallery, credited) **plus** a box for any pasted move sequence.
- Two start points: **Solved cube** (play the pattern's classic moves) and **My cube now** (direct ~20-turn route from any state, incl. pattern → pattern).
- Native support for slice/wide/rotation notation (`M E S`, `r`/`Rw`, `x y z`).
- When switching to Solve after a pattern/playback, Solve loads "my cube now" so the user can solve back without repainting.

Already verified (read-only prototypes): all 110 ruwix algorithms parse in cubejs; 109 unique states (Tetris == Yan Ying); none identity; exactly 3 move centers (Perpendicular lines, Don't cross line, Flower field). Direct-route math prototype: 40/40 random cubes in 4 holds land exactly on the pattern, pattern→pattern works, centers-moved target works, ≤ 22 turns. Kociemba for all 110 patterns: worst 0.76 s.

Project: `D:\Projects\rubiks-solver` (main, clean, 49 tests). Work on branch `feature/patterns`; TDD per unit; native execution; one fresh reviewer at the end; save this plan to `docs/superpowers/plans/2026-09-28-patterns.md` as the record.

## Design

### 1. `js/cube.js`: one geometry table, new moves, parser
- Internal `LAYERS` table `{axis, inLayer}` for `U R F D L B`, slices `M` (axis = L normal, |x|<.5), `E` (D normal, |y|<.5), `S` (F normal, |z|<.5), wide `r l u d f b` (face normal, dot(p,n) > -0.5), rotations `x y z` (all). `BASE`/`PERMS`/`MOVES` (54) **and** `moveGeometry` both read it. `view3d.js` then animates new moves unchanged (center cubies are ordinary cubies).
- `parseAlgorithm(text, {maxMoves = 1000}) → {moves} | {error, at}`:
  - normalizes `’ ‘ ′ ´` → `'`, `2'`/`'2` → `2`, `Rw` → `r`
  - accepts no-space input (`RUR'U'`), `( … )` groups, `( … )N`, `x N` / `× N` / `* N` repeats, nested groups via a stack
  - rejects `[`, `R3`, lowercase `m e s` and unknown moves with a clear message (`Unknown move 'Q' (move 5)`), plus unbalanced parentheses, too long, empty
  - `parseMoves` stays strict.
- `ROTATIONS` (24 sequences from ('',x,x2,x',z,z') × ('',y,y2,y')), `centerKey(state)`, `rotationTo(state, centers) → moves | null`.

### 2. `js/describe.js`: wording for every move
- `TURNS` claims for `M E S`, wide moves (two columns/rows) and `x y z` (a whole face → another face). `describeMove` covers **all** of `M.MOVES` (today it would throw on `x`). Slice/wide wording says centers move too.
- `centerChange(before, after)`: "This turn moves the centers too: afterwards yellow is on top and blue faces you." Empty string if unchanged.
- `pictureHint(state, picture)`: "Hold white on top and green facing you to see it like the picture." Empty string if orientation already matches.

### 3. `js/patterns.js` (new UMD module `CubePatterns`, browser-free)
- `LIBRARY` (109 entries in ruwix order; Tetris has alias "Yan Ying"; ids = list index; explicit names), `SOURCE` credit.
- `entries()` (memoized: moves, state, key), `fromAlgorithm(text)`, `canonicalKey(state)` (rotate to standard centers), `findByKey` (custom alg → "This is Superflip"), `matches(entry, query)`.
- `homes(state)`: home facelet per sticker (piece identification relative to that state's centers).
- `planRoute(from, picture) → {input, target, rotation, relabeled}`:
  1. `T = picture·r` with `r = rotationTo(picture, centers of from)`.
  2. Fallback for mirror/Japanese color schemes: rotate to standard, recolor by the cube's centers, `relabeled: true`.
  3. `R[i] = C[inv(homes(T))[homes(from)[i]]]`.
- The actual search is `Fast.solve(plan.input)`, with no worker changes. `checkRoute(from, plan, moves)` must pass before playing.
- `patternSteps({name, start, moves, kind}) → {states, steps}`: Step shape unchanged. Stage name = pattern name; notes: start instruction on step 0 ("Start from a solved cube, white on top, green facing you" for Solved), `centerChange` on center-moving steps.
- `thumbnailSvg(state)`: isometric U/F/R derived from `FACELETS` pos/normal, class-based fills (`.s-w` …) for theme tokens.

### 4. UI (`index.html`, `js/app.js`)
- **Header:** Solve | Patterns switch (`aria-pressed`). Mode switches during a turn go through `player.afterTurn`.
- **"My cube now":** `app.physical = {state, label}`, set when validation passes and from player `onChange` when not busy. Labels: "Your checked cube", "Turn 12 of 20 · Superflip", "End of Superflip". Jumps don't pretend the real cube turned: the label says where it came from, next to its mini net.
- **Patterns panel:** search, custom-sequence box (errors via `textContent`), detail box above the grid. The detail box holds the name/alias credit, the moves, Start from (Solved: N moves / My cube now: mini net + label), Show me and status. The grid is built lazily on first visit, with `content-visibility:auto`. Selecting a card shows the pattern in the 3D view. Phones: `.is-patterns .viewer` sticky about 28vh; the detail box scrolls into view.
- **Route requests:** computed only when "My cube now" is selected. Debounced 150 ms, `routeSeq` drops stale replies, cached by from|target key. Handles:
  - `loading` → "Preparing solver…"
  - `failed` → "The route finder couldn't load"
  - `SOLVER_RESTARTING`
  - empty route → "Your cube already shows this pattern"
  - route failure → message + cube code
- **Playback:** same player. Stage line "Pattern · name". `btn-edit` reads "← Patterns". End card "Pattern done" + `pictureHint`.
- **Solve:** after an `await`, `solve()` ignores a result if the mode changed. Entering Solve with a physical state different from the last check loads it into the net with note "Loaded from: End of Superflip".
- **Credit:** ruwix.com link (`target=_blank rel="noopener noreferrer"`). Script order: `patterns.js` after `describe.js`, before `app.js`.

## Tests (Node, written first)
**cube:**
- Every new move: permutation, order 4, `X2`, `X X'`.
- Identities: `M ≡ x' R L'`, `r ≡ R M'`, `E ≡ y' U D'`, `S ≡ z F' B`, etc.
- Slices and wide moves move exactly 4 centers.
- **Geometry vs PERMS for all 54 moves** (pins the animation).
- **cubejs cross-check**: 200 random 20-move sequences over all moves, compared by color identity (not `toFaceletString`).
- Rotations: 24 distinct `centerKey`s; `rotationTo` finds the rotation, and returns null for a red/orange swap.
- Parser cases, e.g. `R U2' F’ D'2`, `RUR'U'`, `Rw`, `(R U R' U')3`, nested groups, the errors, the length cap.

**describe:**
- Claims hold for every `TURNS` key.
- All 54 moves are described, with no "undefined".
- `centerChange` and `pictureHint` cases.

**patterns:**
- Library:
  - every entry parses and validates
  - none is solved; 109 unique `canonicalKey`s
  - exactly 3 move centers
  - each matches cubejs by color identity
  - superflip and checkerboard spot checks
- `homes`: identity on all 24 rotations; `homes(SOLVED·A)[perm[i]] === i`.
- Routes:
  - 10 scrambles × 6 patterns, plus the same in random holds
  - pattern → pattern
  - already-there → empty
  - red/orange-swapped cube (`relabeled`)
  - all ≤ 22 turns
- Every library pattern reachable from solved.
- `patternSteps` notes and indices.
- `matches`: "plus", "yan", empty.
- `thumbnailSvg`: 27 stickers, orientation checks.
